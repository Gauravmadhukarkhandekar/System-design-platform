# Database Isolation Levels

Control how transactions interact with each other. Trade consistency for performance.

## The bank account analogy

<Callout variant="tip" title="Simple analogy">
You and your spouse both check your joint bank balance ($1000) at the same time, then both try to withdraw $800.

**Poor isolation:** Both see $1000 → Both withdraw → Account goes -$600!

**Good isolation:** First withdrawal locks account → Second sees $200 → Correctly denied
</Callout>

Isolation levels control how much transactions can "see" each other's uncommitted work.

Understand the trade-off: Higher isolation = more consistent but slower. Be ready to explain when you'd use each level and why.
</Callout>

## Key takeaways

<SummaryBox title="Key takeaways">
- Isolation levels control how much transactions can see each other's uncommitted work.
- Read Committed is the most common default — prevents dirty reads.
- Serializable prevents all anomalies but is slowest.
- Higher isolation = more consistency but worse performance.
- Know the anomalies: dirty read, non-repeatable read, phantom read.
- In critical systems (banking), use higher isolation for sensitive operations.
</SummaryBox>
