# SOLID Principles

## Introduction

SOLID is a set of five design principles for object-oriented design that lead to more maintainable and flexible code.

## The Five Principles

1. **S - Single Responsibility**: A class should have one reason to change (one responsibility).
2. **O - Open/Closed**: Open for extension, closed for modification. Prefer extending behavior via new code rather than changing existing code.
3. **L - Liskov Substitution**: Subtypes must be substitutable for their base types without breaking correctness.
4. **I - Interface Segregation**: Prefer many specific interfaces over one large interface so clients depend only on what they use.
5. **D - Dependency Inversion**: Depend on abstractions (interfaces), not concretions. High-level modules should not depend on low-level details.

## Summary

- SOLID guides you toward small, focused classes and dependencies on abstractions.
- Applying these principles improves testability and reduces coupling.
