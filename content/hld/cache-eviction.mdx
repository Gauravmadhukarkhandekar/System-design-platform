# Cache Eviction Policies

When the cache is **full**, something has to go. The **eviction policy** decides **which** key leaves — and that choice **directly drives hit rate**, tail latency, and how much useful data stays hot.

## The closet analogy

<Callout variant="tip" title="Simple analogy">

</Callout>

Production caches often use **maxmemory** + **LRU/LFU/FIFO** **and** **TTL** on keys (e.g. Redis `volatile-*` vs `allkeys-*`). Freshness and capacity are **two** different knobs.
</Callout>

## LRU implementation (interview classic)

**Data structures:** **hash map** (key → list node) + **doubly linked list** ordered by recency (**head** = most recent, **tail** = least recent, or the reverse — stay consistent in the interview).

```python
class Node:
    def __init__(self, key=0, val=0):
        self.key, self.val = key, val
        self.prev = self.next = None

class LRUCache:
    def __init__(self, capacity: int):
        self.cap = capacity
        self.map = {}  # key -> Node
        self.head = Node()
        self.tail = Node()
        self.head.next = self.tail
        self.tail.prev = self.head

    def _add_first(self, node):
        n = self.head.next
        self.head.next = node
        node.prev = self.head
        node.next = n
        n.prev = node

    def _remove(self, node):
        p, n = node.prev, node.next
        p.next = n
        n.prev = p

    def get(self, key):
        if key not in self.map:
            return -1
        node = self.map[key]
        self._remove(node)
        self._add_first(node)
        return node.val

    def put(self, key, value):
        if key in self.map:
            node = self.map[key]
            node.val = value
            self._remove(node)
            self._add_first(node)
            return
        if len(self.map) >= self.cap:
            lru = self.tail.prev
            self._remove(lru)
            del self.map[lru.key]
        node = Node(key, value)
        self.map[key] = node
        self._add_first(node)
```

## Policy comparison

<MetricTable
  title="Which policy when (rules of thumb)"
  columns={['Policy', 'Best for', 'Avoid when']}
  compact
  rows={[
    ['LRU', 'General web and API caching; shifting “working set”.', 'Huge one-time scans that flood the cache (consider scan resistance or TTL).'],
    ['LFU', 'Stable hot-key distributions (some CDN / object caches).', 'Access mix changes abruptly — old “stars” block new hot data.'],
    ['FIFO', 'Streaming buffers, very simple embedded caches.', 'Items have very different business value or hit rates.'],
    ['TTL', 'Sessions, tokens, feature flags, “good enough” freshness.', 'You only care about frequency, not age of validity.'],
  ]}

## Key takeaways

<SummaryBox title="Cache eviction — recap">
- **Eviction** is mandatory when the cache is **bounded** — policy choice **strongly** affects **hit rate**.
- **LRU** is the **default mental model** for many systems: evict **least recently used**; implement with **map + doubly linked list** for **O(1)** get/put.
- **LFU** favors **frequency**; watch **inertia** of old hot keys when traffic **shifts**.
- **FIFO** is **simplest** but **blind** to usage; **Random** is easy but **noisy**.
- **TTL** addresses **freshness**; combine with **capacity** policies in real engines (**Redis**, CDNs, in-process caches).
- In interviews: **draw** the list + map, state **invariants** (MRU/LRU ends), and connect to **production** approximations.
</SummaryBox>
